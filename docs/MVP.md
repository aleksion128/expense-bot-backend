# Personal Finance MVP

## Что уже есть в репозитории

Единственная ветка: `master` (других нет).

Это Go API (`Gin` + `PostgreSQL`), изначально под Telegram-бот учёта расходов:

| Есть | Нет |
|------|-----|
| CRUD расходов | Счета (карта / накопительный / брокер / наличные) |
| CRUD доходов (месяц/год) | Импорт CSV/XLSX |
| CRUD финансовых целей | Переводы между своими счетами |
| AES-шифрование описаний | Бюджет и прогноз |
| Пользователь по `telegram_id` | Сценарии «что если» |
| Dockerfile бэкенда | Frontend |

Связанные репозитории (не в этом репо):
- `expense-bot` — Python Telegram-бот (aiogram), статистика/графики
- `budgetly.bot.io` — лендинг

## Цель MVP

Веб-приложение в **этом** репозитории: загрузил выписку → получил аналитику.

### Must-have
1. **Счета** — карта, накопительный, брокерский, наличные
2. **Импорт** CSV/XLSX (Тинькофф + универсальный формат) + автокатегоризация
3. **Транзакции** — доход / расход / перевод (переводы ≠ расходы)
4. **Бюджет** — плановые доходы, регулярные траты, крупные покупки
5. **Прогноз** — остаток через 1 / 3 / 6 месяцев
6. **Сценарии** — «что если куплю X за N ₽»
7. **Frontend** — дашборд, счета, импорт, бюджет, цели, сценарии

### Out of scope для v1
- Полноценный auth (OAuth/JWT) — демо-пользователь
- Полная поддержка всех банков РФ
- Инвестиционный P&L брокера
- Мобильное приложение / Telegram Mini App

## Архитектура

```
/
├── backend/          # Go API (эволюция текущего кода)
├── frontend/         # React + Vite + TypeScript
├── migrations/       # SQL schema
├── docker-compose.yml
└── docs/
```

Деньги храним в **копейках** (`int64`), чтобы избежать float.

## Доменная модель

- `users` — пользователь (для MVP один демо-user)
- `accounts` — счета капитала
- `transactions` — единый журнал (income / expense / transfer)
- `categories` — категории + ключевые слова для автокатегоризации
- `budget_items` — planned_income | recurring_expense | large_purchase
- `goals` — финансовые цели
- `import_batches` — история загрузок выписок

## Прогноз (формула MVP)

```
баланс(t) = Σ balances
          + Σ плановых доходов за период
          − Σ регулярных трат за период
          − Σ крупных покупок с due_date в периоде
          + Σ факт. доходов − Σ факт. расходов (если смотрим «хвост» текущего месяца)
```

Сценарий «что если» = тот же прогноз минус сумма покупки (опционально с датой).
